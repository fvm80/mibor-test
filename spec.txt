ТЗ: приложение учёта малого бизнеса (PWA + Google Sheets)
Документ для ИИ-разработчика. Версия 1.0, 22.11.2026. Автор требований: FVM.
1. Контекст и цель
Один пользователь, бизнес без работников. Он делает заказы (изделия, услуги), получает и тратит деньги в нескольких валютах, даёт и берёт в долг. Нужно простое приложение для личного учёта: деньги, долги, заказы с планом и фактом, прогноз.
Использование в основном с телефона как PWA (иконка на главном экране).
Интерфейс только на русском.
Данные лежат в Google Таблице пользователя, её можно открыть и поправить руками.
Это не бухгалтерская система: без налогового учёта, без нескольких пользователей, без банковских интеграций.
2. Технические ограничения
Фронтенд: HTML + CSS + ванильный JavaScript (ES-модули). Без фреймворков и без этапа сборки. Все библиотеки (если нужны) кладутся в репозиторий локально, без CDN, иначе офлайн не заработает.
Бэкенд: Google Apps Script (Web App). Хранилище: Google Sheets.
Хостинг статики: GitHub Pages или любой HTTPS-хостинг.
Экран: mobile-first (360–430 px). На десктопе приложение показывается колонкой шириной до 480 px по центру.
Суммы: числа с двумя знаками. Любой агрегат округляется до 2 знаков в конце расчёта, а не на каждом шаге.
Даты: в таблице формат yyyy-mm-dd, служебные метки времени ISO UTC. В интерфейсе дд.мм.гггг, локаль ru-RU.
Часовой пояс скрипта: задаётся в настройках проекта Apps Script (как у пользователя).
Код валюты лея: в приложении MDL (ISO-код). Пользователь в черновике писал «MLD», это опечатка, в интерфейсе показывать MDL.
3. Архитектура
Три слоя: PWA ↔ Apps Script ↔ Google Sheets.
Расчёты только на клиенте. Лист это хранилище сырых записей без формул. Балансы, остатки долгов, планы и прогнозы считаются в JS. Расчёты вынести в отдельный модуль чистых функций (calc.js, без DOM) и покрыть тестами на данных из раздела 10.
Локальный кэш. При запуске приложение мгновенно показывает данные из IndexedDB и в фоне вызывает sync.
ID создаёт клиент (crypto.randomUUID()), поэтому записи можно создавать офлайн без конфликтов.
Мягкое удаление. Колонка deleted (TRUE/FALSE), строки не удаляются физически. Удалённые записи нигде не учитываются.
Конфликты: побеждает запись с большим updated_at (last-write-wins). Сервер при записи ставит свой updated_at.
Запись под блокировкой: LockService.getScriptLock(), ожидание до 10 с.
3.1 API Apps Script
Один endpoint. doPost принимает JSON в теле, а Content-Type: text/plain;charset=utf-8 (так браузер не делает preflight-запрос и CORS не мешает). Ответ отдаётся через ContentService как JSON. fetch следует редиректу Apps Script (по умолчанию). doGet возвращает только {ok:true} (проверка доступности).
Запрос: { "token": "...", "action": "...", "payload": {...} }. Ответ: { "ok": true, "data": {...}, "serverTime": "ISO" } или { "ok": false, "error": "код" }.
Триггер по времени updateRates запускается каждые 3 часа.
3.2 Защита
Web App: исполнять от имени владельца, доступ «Все». Доступ ограничивает секретный токен.
Токен хранится в Script Properties (API_TOKEN) и сверяется в каждом запросе. Неверный токен даёт unauthorized без данных.
На телефоне токен и URL скрипта вводятся один раз в Настройках и хранятся локально. В репозитории их быть не должно.
4. Модель данных (листы Google Sheets)
Общие правила: заголовки в строке 1 на английском, без объединённых ячеек, без формул. Во всех листах кроме rates и settings служебные колонки id, created_at, updated_at, deleted.
4.1 Лист ops: операции (факт, двигают деньги)
4.2 Лист orders: заказы
name, client, status (planned, in_progress, done, cancelled), currency (одна валюта заказа), price (плановая цена для клиента в валюте заказа), start_date, due_date, closed_at, note.
4.3 Лист order_lines: позиции плана заказа
order_id, type, name, qty, unit, unit_price, plan_amount, currency, fact_amount, note, sort.
Типы type: material (материалы), service (услуги), overhead (электричество и прочие накладные), other (прочее), labor_own (моя работа, не деньги).
plan_amount хранится всегда. Если заданы qty и unit_price, то plan_amount = qty × unit_price, иначе вводится вручную.
fact_amount используется только для labor_own (фактическая оценка труда). Для остальных типов факт считается из ops.
Валюта позиции может отличаться от валюты заказа.
4.4 Лист debts: долги
direction (owed_to_me — мне должны, i_owe — я должен), counterparty, amount, currency, date, due_date, purpose, order_id, cash_moved (TRUE/FALSE), status (open, closed, written_off), note.
4.5 Лист rates: курсы (одна строка на валюту, кроме базовой)
currency, rate_auto (базовых единиц за 1 единицу валюты), rate_auto_at (ISO), rate_manual, mode (auto или manual), source.
4.6 Лист settings: пары key, value (JSON)
base_currency (по умолчанию MDL), currencies (по умолчанию ["MDL","USD","EUR"]), categories_income, categories_expense, last_currency.
5. Бизнес-правила и формулы
Все перечисленные записи берутся без deleted. rate[cur] это актуальный курс (раздел 6), для базовой валюты 1. Конвертация в базовую: amount × rate[cur].
Деньги
Влияние операции на кассу: income даёт +amount, expense даёт −amount.
Доступно[валюта] это сумма влияний всех операций этой валюты.
Долги
Остаток долга = amount − Σ погашений (операции с этим debt_id и debt_role = repayment).
Валюта погашения должна совпадать с валютой долга (в v1 иначе ввод запрещён).
При остатке ≤ 0 статус автоматически становится closed. Есть ручные действия «закрыть» и «списать» (written_off, остаток перестаёт учитываться).
Если cash_moved = TRUE, при создании долга автоматически создаётся операция principal: для owed_to_me это expense (я отдал деньги), для i_owe это income (я их получил). При изменении или удалении долга связанные операции обновляются вместе с ним. Удалять долг с погашениями только после подтверждения (погашения удаляются тоже).
Операции с debt_id не считаются доходом или расходом бизнеса. Они двигают кассу, но не входят в отчёты «доходы и расходы» и в прибыль заказов.
Мне должны[валюта] и Я должен[валюта] это суммы остатков открытых долгов соответствующего направления.
Заказ (суммы приводятся к валюте заказа по текущим курсам; операции в валюте заказа конвертации не требуют)
Плановые затраты = Σ plan_amount позиций, кроме labor_own.
Плановая прибыль (деньги) = price − плановые затраты.
Плановая прибыль сверх моей работы = price − плановые затраты − Σ plan_amount(labor_own).
Факт по позиции = Σ расходов с этим order_line_id. Расходы с order_id, но без позиции идут в группу «Внеплановые».
Фактические затраты = Σ расходов с этим order_id (кроме операций с debt_id).
Получено = Σ доходов с этим order_id (кроме операций с debt_id).
Фактическая прибыль = Получено − Фактические затраты.
Отклонение по позиции = факт − план (положительное значение это перерасход).
Ожидается поступлений = max(0, price − Получено) для заказов в статусах planned и in_progress.
Ожидается расходов = Σ по позициям max(0, plan_amount − факт по позиции) для таких же заказов, кроме labor_own.
Для заказов done и cancelled ожидаемые суммы равны нулю.
Завершение заказа: оставшийся плановый расход отбрасывается. Если Получено < price, приложение предлагает создать долг owed_to_me (cash_moved = FALSE) на разницу и привязать его к заказу.
Главная страница
Прогноз = Доступно + Мне должны − Я должен + Ожидается поступлений − Ожидается расходов, всё в базовой валюте, и отдельно по каждой валюте.
Предупреждения: просроченные долги (due_date в прошлом), Прогноз < 0, заказы с перерасходом.
6. Курсы валют
Требования пользователя: показывать курс на главной странице, только текущий (без истории). Если получить свежий не удалось, используется полученный ранее или введённый вручную.
Курс это сколько базовых единиц (MDL) за 1 единицу валюты. Для каждой небазовой валюты есть режим auto или manual (по умолчанию auto).
Какой курс берётся в расчёты (по порядку):
mode = manual и rate_manual задан, берётся rate_manual.
Иначе rate_auto, если он есть (даже если старый).
Иначе rate_manual, если он есть.
Иначе курса нет: валюта показывается отдельно, в итоги в базовой валюте не входит, на главной предупреждение «нет курса для X».
Автоматическое получение делает сервер (UrlFetchApp в Apps Script), поэтому проблем с CORS нет. Основной источник: официальные курсы Национального банка Молдавии в XML (ожидаемый адрес вида https://www.bnm.md/en/official_exchange_rates?get_xml=1&date=ДД.ММ.ГГГГ). Разработчик обязан проверить актуальный адрес и формат ответа при разработке, а также учесть поле номинала (курс может быть за 1, 10 или 100 единиц: делить на номинал). Запасной источник: бесплатный публичный API курсов, в котором есть MDL. Источник пишется в rates.source.
Когда обновляется: триггер каждые 3 часа; плюс при запуске приложения клиент вызывает refreshRates, если rate_auto_at старше 1 часа и есть сеть. Ошибка получения не стирает предыдущее значение.
Курс перезаписывается, история не хранится (одна строка на валюту).
Официальный курс может отличаться от курса банка или обменника, поэтому ручной режим обязателен.
На главной: строка «USD 18,20 · EUR 20,00» и подпись «обновлено 22.11 10:05, авто» или «вручную». Если автокурс старше 24 часов или нет связи, жёлтая пометка «курс от <дата>». Нажатие на курс открывает диалог: автозначение (только чтение), поле ручного курса, переключатель «Авто / Вручную», кнопка «Обновить сейчас».
В v1 все конвертации идут по текущему курсу. Поле ops.rate_at_entry записывается «на будущее». Заказ в своёй валюте конвертации не требует, поэтому его прибыль не «плавает».
7. Интерфейс
7.1 Общая структура
Верхняя панель: название экрана; справа шестерёнка ⚙ (Настройки) на всех экранах; слева индикатор синхронизации (зелёный — всё сохранено, жёлтый — есть неотправленные изменения, красный — ошибка, серый — офлайн).
Нижняя панель на всех экранах: Главная · Операции · ＋ · － · Заказы · Долги. Кнопка «＋» (зелёная, круглая) открывает быстрый ввод дохода, «－» (красная, круглая) — расхода. Остальные кнопки это вкладки с иконкой и подписью, активная подсвечена.
Светлая и тёмная тема по настройке устройства. Цели нажатия не меньше 44 px. Суммы с пробелом как разделителем тысяч и запятой как десятичным знаком.
Навигация: SPA с hash-маршрутами (#/home, #/ops, #/orders, #/orders/<id>, #/debts, #/settings); кнопка «назад» телефона работает.
7.2 Форма «＋ Доход» / «－ Расход» (нижняя шторка)
Вверху переключатель типа Доход / Расход (можно менять прямо в форме). Поля:
Сумма (числовая клавиатура, обязательно, > 0).
Валюта (чипы из настроек, по умолчанию последняя использованная).
Дата (по умолчанию сегодня).
От кого (для дохода) / Кому (для расхода), с подсказками из прошлых значений.
За что (тоже с подсказками).
Категория (необязательно).
Заказ (необязательно, список активных заказов). Для расхода после выбора заказа появляется поле Позиция плана (список позиций заказа с подписью «план X, факт Y», необязательно).
Примечание.
Кнопки: «Сохранить» и «Сохранить и добавить ещё». Сохранение мгновенное (в локальную БД), синхронизация в фоне. После сохранения короткий toast с кнопкой «Отменить» (5 с). Привязка к долгу из этой формы не делается, долги и погашения вводятся на странице «Долги».
7.3 Главная
Сверху вниз:
Курсы (раздел 6).
Главная карточка: крупно «Доступно сейчас» в MDL, под ним «Прогноз» в MDL с подписью формулы.
Сетка из 4 плиток: «Доступно», «Мне должны», «Я должен», «Ожидается по заказам» (со строками «+поступления» и «−расходы»). Нажатие на плитку разворачивает разбивку по валютам: «MDL 12 400 · USD 1 900 (= 34 580 MDL)».
Предупреждения (если есть, раздел 5).
Активные заказы (до 5): название, «получено / цена», полоска «затраты факт / план», прибыль. Тап открывает заказ.
Ближайшие долги (до 3, просроченные выше).
Последние 5 операций.
Pull-to-refresh запускает sync.
7.4 Страница «Операции» (фактические доходы и расходы)
Список по датам (новые сверху): цвет и знак, сумма с валютой, «контрагент · за что», метки (заказ, долг).
Фильтры-чипы: период (месяц по умолчанию, неделя, всё, выбрать), тип, валюта, заказ, категория; поиск по тексту.
Итоги периода сверху: доходы, расходы, разница (по валютам и в MDL). Операции с debt_id в списке видны с меткой «долг», но в итоги не входят (подпись «без долговых операций»).
Тап по операции открывает карточку: редактирование всех полей, мягкое удаление с подтверждением. У операций с debt_role сумма, валюта и тип не редактируются здесь, есть ссылка «изменить в долге».
7.5 Страница «Заказы»
Список: фильтр по статусу («Активные» = planned + in_progress по умолчанию, «Завершённые», «Все»). Карточка: название, клиент, статус, срок, «получено / цена», «затраты факт / план», прибыль. Кнопка «Новый заказ». Форма создания минимальная: название, клиент, валюта, цена. Позиции плана можно добавлять сразу пачкой или позже.
Карточка заказа (#/orders/<id>), сверху вниз:
Шапка (редактируемая): название, клиент, статус (planned → in_progress → done или cancelled), валюта (нельзя менять, когда уже есть операции), цена, даты, примечание.
Сводка «план / факт / разница»: цена и получено; затраты; прибыль (деньги); моя работа; прибыль сверх моей работы; ожидается поступить; ожидается потратить. Перерасход красным, экономия зелёным.
Позиции плана, сгруппированные по типу: название, план, факт, отклонение. Добавление позиции: тип, название, количество, единица, цена за единицу, валюта, сумма, примечание. Тап по позиции показывает связанные операции и кнопки «+ Факт» (открывает форму расхода с уже выбранными заказом и позицией), «Изменить», «Удалить». Для labor_own вместо операций поле «факт (оценка)».
Внеплановые расходы: операции заказа без позиции, с кнопкой «Привязать к позиции».
Поступления от клиента: доходы заказа и кнопка «+ Поступление» (форма дохода с заказом).
Действия: «Копировать как новый заказ» (позиции и плановые суммы без фактов), «Завершить» (диалог из раздела 5), «Отменить», «Удалить».
7.6 Страница «Долги»
Две вкладки: «Мне должны» и «Я должен». Сверху итог по валютам и в MDL.
Строка: контрагент, за что, «остаток / исходная сумма», срок, статус (открыт, частично, просрочен). По умолчанию только открытые, есть фильтр «закрытые».
«Новый долг»: направление, контрагент, сумма, валюта, дата, срок (необязательно), за что, заказ (необязательно) и переключатель «Деньги уже двигались». Значения по умолчанию нет, выбор обязателен. Подпись зависит от направления: «Я отдал деньги» или «Я получил деньги», и под переключателем пояснение, что будет создана связанная операция.
Карточка долга: история (выдача и погашения), кнопки «Погасить» (сумма по умолчанию равна остатку, дата; создаёт repayment: для owed_to_me это income, для i_owe это expense), «Закрыть без оплаты» (written_off, с подтверждением), «Изменить», «Удалить».
7.7 Настройки (шестерёнка вверху справа)
Подключение: URL скрипта, токен, кнопки «Проверить связь» (ping) и «Инициализировать таблицу» (init).
Валюты: базовая (MDL; после появления данных менять нельзя), список валют (добавление по коду ISO 4217, удаление только если нет записей), режим курса по каждой валюте.
Категории доходов и расходов: добавить, переименовать, скрыть. Набор по умолчанию для расходов: материалы, услуги, электричество, инструмент, транспорт, налоги, прочее; для доходов: оплата заказа, продажа, прочее.
Данные: «Синхронизировать сейчас», «Экспорт в JSON и CSV» (скачивание файла), «Очистить локальный кэш» (с предупреждением, если есть неотправленные изменения).
О приложении: версия, время последней синхронизации.
8. PWA, офлайн и синхронизация
manifest.webmanifest: название «Учёт», display: standalone, lang: ru, start_url: ./#/home, иконки 192 и 512 px (включая maskable), цвета темы. Иконки можно нарисовать простыми (например, буква «У» на цветном фоне).
Service Worker: предзагрузка оболочки (HTML, CSS, JS, иконки), стратегия cache-first, версионированное имя кэша. При новой версии toast «Доступна новая версия, обновить». Запросы к Apps Script в кэш Service Worker не попадают.
Локальная БД (IndexedDB): хранилища ops, orders, order_lines, debts, settings, rates, meta (since, deviceId, URL, токен), outbox.
Очередь изменений (outbox): каждое изменение кладёт в очередь запись целиком (upsert). sync отправляет очередь и при успехе её очищает. При ошибке повтор с растущей паузой. Данные никогда не теряются из-за ошибки сети.
Когда запускается sync: старт приложения, возврат на передний план (visibilitychange), событие online, через 2 с после любого изменения, pull-to-refresh, кнопка в настройках.
Первый запуск: экран настройки подключения (URL, токен), затем ping, init, полный sync.
iOS: учесть safe-area (viewport-fit=cover, env(safe-area-inset-*)), шрифт полей ввода не меньше 16 px (иначе Safari масштабирует экран), подсказка «Поделиться → На экран «Домой»» (события beforeinstallprompt там нет). На Android кнопка «Установить» в настройках.
Цели: открытие из кэша менее секунды; расчёты на 5 000 операций мгновенные (для списков без виртуализации достаточно постраничной подгрузки по 50 записей).
9. Этапы и критерии приёмки
После каждого этапа разработчик отдаёт работающую версию, список файлов, пошаговую инструкцию развёртывания и чек-лист проверки, и ждёт подтверждения пользователя.
Этап 0. Связь. Таблица, Code.gs (ping, init, sync, токен, LockService), минимальный клиент. Приёмка: запись, созданная с телефона, появляется строкой в таблице; правка в таблице видна в приложении после sync; неверный токен не даёт данных.
Этап 1. Каркас, журнал, главная, курсы, PWA. Нижняя панель, формы «＋» и «－», страница «Операции», главная (курсы, «Доступно»), настройки, автокурс + ручной режим, манифест, Service Worker, IndexedDB, outbox. Приёмка: ввожу доходы и расходы в трёх валютах, баланс на главной совпадает с расчётом вручную; в режиме самолёта записи создаются и после возврата сети попадают в таблицу; если курс не получен, берётся предыдущий или ручной; приложение устанавливается на главный экран телефона.
Этап 2. Долги. Страница «Долги», создание с флагом cash_moved, частичное и полное погашение, списание, плитки «Мне должны» и «Я должен» на главной. Приёмка: тесты из раздела 10 (долги) проходят; погашение создаёт операцию и уменьшает остаток; операции с debt_id не попадают в итоги «доходы/расходы».
Этап 3. Заказы (план и факт). Список и карточка заказа, позиции плана, привязка операций к заказу и позиции, сводка план/факт, завершение с долгом на остаток, копирование. Приёмка: тест заказа из раздела 10 даёт ожидаемые числа; добавление факта из карточки позиции работает в два нажатия.
Этап 4. Прогноз, предупреждения, экспорт, доводка. Плитка «Ожидается по заказам», «Прогноз», предупреждения, экспорт JSON и CSV, тёмная тема, доступность, проверка на iOS и Android. Приёмка: все тесты раздела 10 проходят, приложение работает без сети и не теряет данные.

Погашение долга Олега на 200 EUR даёт остаток 400 EUR, доступно EUR 200, «Мне должны» в MDL уменьшается на 4 000, а «Доступно» увеличивается на 4 000. Итоги «доходы/расходы» не меняются.
10.3 Заказ (новый, не из черновика)
Заказ «Тестовый», валюта USD, цена 1 900. Позиции: материалы 600, фурнитура 150 (material), электричество 40 (overhead), моя работа 400 (labor_own).
Плановые затраты 790; плановая прибыль (деньги) 1 110; прибыль сверх моей работы 710.
Факт: расход 640 USD на позицию «материалы» → отклонение +40 (перерасход).
Поступление 950 USD от клиента → получено 950, ожидается поступить 950.
Ожидается потратить 190 (фурнитура 150 + электричество 40; по материалам перерасход даёт 0; моя работа не считается).
Завершение заказа предлагает создать долг owed_to_me 950 USD (cash_moved = FALSE), ожидаемые суммы по заказу становятся 0.

13. Принятые решения (для справки)
Базовая валюта MDL; валюты MDL, USD, EUR, список расширяется в настройках.
У заказа одна валюта; позиции плана могут быть в других валютах и пересчитываются по текущему курсу.
Моя работа это неденежная позиция (labor_own), прибыль показывается двумя числами.
Налоги и НДС не ведутся, есть только категория «налоги».
Фото чеков в первой версии нет.
Все курсы только текущие (без истории); ручной курс перекрывает автоматический, если включён режим «Вручную».
Погашение долга только в валюте долга.
